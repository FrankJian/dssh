# 远程 Explorer 增强规格

> 状态：阶段 A–E 已实现，待真实主机回归验证。基础 Explorer 已支持目录树、上传下载、新建、重命名和删除文件 / 空目录；本规格记录其实现顺序与安全边界。

## 1. 范围与原则

- Explorer 只通过 Rust `SftpManager` 操作远端文件系统，并沿用 SSH TOFU 主机密钥校验。
- 禁止用终端 shell 拼接 `rm`、`mv`、`mkdir`，也不把远端路径交给前端直接处理。
- 所有破坏性或批量操作需先说明作用范围，失败项保留可读错误；默认安全优先于“像 VS Code 一样快”。
- 现有 `RemoteFileTree` 负责树与选中态，`RemoteFileEditor` 负责打开文件及其未保存保护；传输和文件系统行为抽为可复用 hook / service，供全页 `FileBrowser` 复用。

## 2. 当前基线

- 懒加载目录树、路径输入、展开 / 收起。
- 上传文件、下载文件、目录打包下载。
- 新建空文件 / 文件夹、重命名、删除文件、删除空目录。
- 文件树右键菜单、文件标签和文本 / 图片 / Markdown 打开体验。

## 3. 实施阶段

### 阶段 A：传输任务与本地拖放 · P1 · 已完成

**目标**：让 Explorer 与现有全页 SFTP 有一致、可观察的传输体验。

- 将现有下载进度事件扩展为带 `operationId`、方向、文件名、已传输大小和总大小的统一传输事件。
- 上传改为流式复制并发出进度；当前实现会一次性读入本地文件，需先消除该内存风险。
- 新增 Explorer 内本地文件拖放上传，复用 `FileBrowser` 使用的 Tauri webview drag-drop 监听；落点是悬停的目录，未命中时为当前根目录。
- 同时传输多个文件时串行队列化，显示当前任务与完成 / 失败汇总；暂不做并发上传。

**实现结果**：后端通过 `sftp://transfer-progress` 为上传、文件下载与目录打包下载统一发送 `operationId`、方向、远端路径、字节数和完成状态；上传以 64 KiB 块流式复制。Explorer 支持从本机拖放文件到根目录或悬停目录，并串行处理每个文件、显示当前进度与最终成功 / 失败汇总。

**验收**：大文件上传 / 下载能持续显示进度；取消文件选择无副作用；拖到目录、根目录和 Explorer 外行为清晰；失败后树仍可刷新。

### 阶段 B：选择模型与批量操作 · P1 · 已完成

**目标**：支持安全、可预测的多选，而不引入传统文件管理器的隐式危险行为。

- `RemoteFileTree` 维护 `selectedPaths: Set<string>` 和锚点；普通点击单选，⌘/Ctrl 点击切换，Shift 点击按当前可见扁平树范围选择。
- 顶部出现紧凑的“已选 N 项”操作条：下载、删除、清除选择；新建和重命名保持单项操作。
- 批量下载使用传输队列；目录仍打包下载。
- 批量删除先展示文件数、目录数及最多若干路径预览，用户确认后逐项执行；已删除项保留，失败项汇总到结果面板。

**验收**：跨展开节点的范围选择稳定；批量操作不会包含不可见或已过期节点；部分失败不掩盖成功项，也不停止后续安全项。

**实现结果**：支持普通点击、⌘/Ctrl 切换和 Shift 可见范围选择；顶部操作条提供批量下载、递归删除和清除选择。批量删除逐项执行并保留失败提示。

### 阶段 C：远端拖拽移动 · P2 · 已完成

**目标**：在同一主机 / profile 内，通过 SFTP rename 实现移动。

- 仅允许拖动已选条目到目录；不支持跨 profile、拖至文件、拖至自身或子孙目录。
- 落点前先检测同名目标；默认取消，提供“替换”必须再确认。替换语义需按 SFTP 服务器能力实测，不能假定 rename 原子覆盖。
- 采用现有 `sftp_rename` 的批量变体；执行后刷新源父目录和目标目录，更新已打开文件标签的路径。
- 第一阶段不实现复制；复制需要完整的远端流式复制和冲突策略，另立任务。

**验收**：禁止非法落点；移动后树、编辑器标签与选中态同步；中途失败能报告未移动项目。

**实现结果**：可将选中项目拖至同 profile 的普通目录；后端拒绝根目录、拖至自身/子孙目录及同名冲突，不支持覆盖。移动完成后刷新树并同步已打开标签路径。

### 阶段 D：递归删除 · P2（最后实施）· 已完成

**目标**：在不借助 shell 的前提下，提供可审计、可取消的递归删除。

- Rust 增加 `sftp_delete_preview`：递归 SFTP `read_dir`，统计文件 / 目录 / 符号链接，限制深度、条目数和预览返回量。
- 前端确认对话框显示目标、统计、前若干路径及“此操作不可恢复”；默认焦点在取消。
- 确认后以深度优先顺序删除：符号链接一律当文件删除，不跟随链接；普通文件先删、目录最后删。
- 使用 operationId + 进度事件 + 取消令牌；取消后停止新的删除请求，并报告已删除 / 未处理 / 失败项。
- 根目录、主目录及用户配置的保护路径不可递归删除。

**验收**：空目录与深层目录、权限拒绝、断线、取消、符号链接、超出预览限制均有安全结果；绝不调用 shell `rm -rf`。

**实现结果**：后端基于 SFTP 递归预览、限制 64 层 / 10000 项，根目录和远程主目录受保护；符号链接不跟随。确认后深度优先删除，统一事件显示进度，并可在执行时请求取消。

### 阶段 E：属性与权限 · P3 · 已完成

- 显示文件大小、修改时间、类型、符号链接目标和 POSIX 权限（服务器支持时）。
- 属性面板允许修改权限，但必须单独确认并明确八进制值；属主 / 属组修改默认不做。
- 读取失败降级为“不可用”，不阻塞文件树。

**实现结果**：右键“属性”显示路径、类型、大小、修改时间、属主/属组和服务器返回的权限；支持明确输入 3/4 位八进制 POSIX 权限后保存。服务器不返回权限时安全降级为只读信息。

## 4. 后端接口演进

| 阶段 | 建议命令 / 事件 |
| --- | --- |
| A | `sftp_transfer_progress`（统一事件）、流式 `sftp_upload` |
| B | 批量请求由前端队列现有单项命令；如需原子语义再增加批量 DTO |
| C | `sftp_move_entries`，输入同 profile 的源路径与目标目录 |
| D | `sftp_delete_preview`、`sftp_delete_recursive`、`sftp_cancel_operation`、删除进度事件 |
| E | `sftp_stat`、`sftp_set_permissions` |

所有载荷保持 camelCase；错误统一映射为用户可读的 `AppError`。新命令必须在 Rust DTO、前端 service、`lib.rs` 注册和测试中同步更新。

## 5. 实施顺序与依赖

1. 先完成阶段 A 的统一传输任务模型，作为 B / C / D 的进度与取消基础。
2. 其次完成阶段 B；它只依赖现有基础 SFTP 命令和阶段 A 队列。
3. 阶段 C 独立实施，但需复用 B 的选择状态。
4. 阶段 D 必须在 A 的 operationId、进度与取消经过真实主机验证后才开始。
5. 阶段 E 最后做，且按服务器差异降级。

## 6. 验证要求

- 每个阶段均在 macOS、Windows 及至少一台真实 SSH/SFTP 主机验证。
- 覆盖权限拒绝、同名冲突、网络中断、符号链接、非 UTF-8 文件名（若服务器支持）和并发打开编辑器的场景。
- 前端运行 `pnpm exec tsc --noEmit`、`pnpm build`；Rust 运行 `cargo fmt`、Clippy（`-D warnings`）和测试。
