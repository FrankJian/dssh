# AI 后台交互会话

状态：2026-10-30 已实现经典文本菜单与 shell 的后台 PTY 路径；真实 JumpServer 与跨平台原生界面待验收。

## 使用方式

在助手中指定已保存的服务器或 JumpServer 目标，助手经确认后在 Rust 中建立后台 SSH 会话，不创建原生窗口、不打开终端标签、不切换当前页面。JumpServer 的 IP 搜索、资产 / 账号选择和目标 shell 后续操作使用同一个 session_id。普通非交互命令仍可直接走后台 exec。

助手顶部出现可折叠的“后台会话”列表，显示名称、真实连接状态，以及“接管”“关闭”按钮。接管显示原会话、回放保留输出并沿用原目标和 shell 状态；AI 后续写入立即被禁止，接管前尚未批准的输入也会失效。接管不会撤回已经提交给服务器的命令。原会话仍运行任务或无法确定状态时，普通终端关闭确认保持生效。

操作确认仍在助手内完成。首次主机密钥、MFA 与密码挑战由现有认证流程交给用户；必要时可接管终端手动完成。API Key、SSH 凭据仍由 Rust 解析，不交给模型。后台会话是真实服务器会话，会占用通道，也可能出现在堡垒机审计中。

## 连接与隔离

- `open_ssh_session` 经批准后直接调用后端会话管理器，默认 PTY 为 120 × 40，返回真实 session_id、连接状态与有界输出，不再发送前端打开标签事件。等待首段输出；已连通但没有输出时约 2 秒返回，仍在连接时最多等 15 秒后返回实际状态，后续继续读取。会话登记不等于连接成功，连接网关也不等于选中目标资产。
- 每个助手实例持有逻辑 conversation_id，跨单轮 run_id 复用后台会话；同一对话、同一服务器配置优先复用现有会话。清空对话会轮换 ID，关闭旧对话未接管的后台会话。
- `list_terminal_sessions` 返回用户可见终端与本对话后台会话，带 background 和真实 status；普通终端枚举排除后台会话。读写校验对话归属，其他对话不能操作。接管后保持原 session_id，所有者信息继续阻止 AI 自动写入或清理用户接管的会话。
- 继续使用既有 SessionManager、SshConnectionPool 和 TOFU。后台输出只保留在有界 Rust 缓存中，不广播至普通前端终端缓冲；后台不启用自动 ZMODEM 文件选择。状态查询已修正为实际状态，避免固定报告 Connected。
- 后台连接断开直接结束，不自动重连并复用旧资产身份。重新建立后，助手必须重新确认菜单、账号与目标，避免在网关 shell 上误执行目标命令。

## 生命周期与并发

每个对话最多 4 个后台会话，应用总计最多 8 个；后台会话空闲 15 分钟后回收，每 30 秒检查。助手读 / 写或复用会话刷新空闲时间，单纯界面轮询不会刷新。

停止助手会取消待确认操作与后续读取；正在新建的连接会关闭，已经存在的会话保留以便后续提问。取消不撤回已经送入 PTY 的命令。后台连接握手期间也处理关闭请求。单独关闭与清空对话只释放所属通道，不断开共享 transport 上的用户终端、SFTP 或转发；关闭通道也不能保证终止已脱离 shell 的远程任务。

接管、开始关闭与 AI 输入版本在同一会话锁下变更。实际写入时再次核对归属、接管 / 关闭状态、输入版本和输出快照，防止确认期间状态变化后仍提交旧输入。

## 实现位置

- `src-tauri/src/ai/background.rs`：后台创建 / 复用、就绪等待、取消清理与工具结果。
- `src-tauri/src/ssh/session_manager.rs`：归属、真实状态、事件隔离、接管、回收、输入并发控制。
- `src-tauri/src/commands/ai.rs`：后台列表、接管、关闭、对话回收命令。
- `src/ai/AiBackgroundSessions.tsx`：轻量后台列表；`useAiChat.ts`：对话标识与清理。
- `src/terminal/useTerminalSessions.ts`：附着原终端、回放输出、恢复目标与运行状态。

## 验证与边界

已通过 TypeScript / 生产构建、Rust 格式化 / Clippy / 全量测试。新增测试模拟无渲染器的同一 PTY 输入队列：IP → 资产编号 → 账号编号 → shell 命令、跨轮归属、其他对话拒绝、真实状态、接管使旧确认失效并禁止未来 AI 输入、关闭 / 接管互斥、空闲时间刷新；前端测试覆盖接管时从输出恢复命令状态。这里的模拟使用输入队列和输出缓存，不是实际 SSH 服务端端到端测试。

真实 JumpServer 账户、认证挑战、真实连接取消 / 空闲回收、后台到可见终端接管和 macOS / Windows 原生点击验收仍待完成。当前验证环境锁屏，未完成原生界面交互验收。

首版支持经典行菜单和 shell。KoKo 的[官方交互处理](https://github.com/jumpserver/koko/blob/dev/pkg/handler/interactive.go)包含经典 `Opt>` / `ReadLine` 与 PTY 尺寸处理，[资产连接实现](https://github.com/jumpserver/koko/blob/dev/pkg/handler/asset.go)在当前会话上建立目标代理；客户端是否展示窗口不影响这一连接方式。不同版本的全屏 TUI 仍需后端 VT 屏幕状态解析与受控按键能力，现有去 ANSI 的追加日志不能完整重建光标移动和擦屏后的屏幕。输出等待目前采用有界轮询；事件驱动增量游标可后续改善吞吐。
