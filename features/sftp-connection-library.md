# SFTP 连接库方案

状态：首版已接入。本地迁移 / 配置 / 搜索 / 导航回归与隔离界面验证通过；真实服务器和跨平台验收见文末。

## 1. 目标与建议

左侧活动栏增加与「连接管理」同级的「SFTP」入口。点击后展开 SFTP 连接侧栏，在主工作区继续使用现有文件管理标签。侧栏负责找连接、分组与启动，文件管理区负责浏览和传输文件。

连接来源包括现有 SSH 配置和新建的 SFTP 配置。两者都复用 SSH 认证与共享连接池；「SSH / SFTP」表示配置分类与默认打开方式，不表示两套互不相通的网络协议。

默认只打开 SFTP 子系统，不创建 shell / PTY。用户明确点击「打开 SSH 终端」时，再复用已有终端或创建 shell 通道。该操作不修改配置类型，也不关闭当前 SFTP。

## 2. 导航与侧栏

活动栏顺序建议为：会话 → 连接管理 → SFTP → S3。SFTP 默认隐藏，可在设置中的导航图标显隐选项中开启；升级时不自动将新入口插入已有导航偏好，保留用户明确保存的显示选择。连接管理中的 SFTP 打开入口继续可用。

- 第一次点击 SFTP：展开连接侧栏，不自动连接任何主机，不替换当前主工作区。
- 再次点击：折叠 / 展开侧栏，文件标签和进行中的传输继续保留。
- 点击侧栏连接：打开或聚焦该配置的 SFTP 标签，保持左侧 SFTP 导航选中；不能沿用当前打开处理器中强制切回「会话」的行为。
- 从 SFTP 打开 SSH 终端：主区切到对应终端，SFTP 侧栏保持展开，方便继续切换主机。
- 连接管理中的 SFTP 类型连接仍统一可见，主操作为「打开 SFTP」；原 SSH 类型连接的主操作保持打开终端。

建议布局：

```text
SFTP                         ＋
[ 搜索名称、地址、目录、标签 ]
[ 全部来源 ▾ ]  [ 目录分组 ▾ ]

▾ 根目录                     6
  ▾ production               3
    [SSH] Cloud API
          deploy@api.example:22
    [SFTP] Backup
           backup@files.example:22
  ▸ home                     2
  [SFTP] Upload
         upload@storage.example:22

底部：6 个连接
```

根目录下直接展示未填写目录的连接，不另设「未分类」。根目录默认展开，子目录默认折叠；每一级目录都可以展开查看该层的连接和子目录。目录数量按子树去重统计。

侧栏使用紧凑树形行；来源筛选采用轻量下拉，目录 / 标签 / 平铺使用图标分段切换。目录展开箭头位于右侧，图标与连接行对齐；主机使用配置图标，突出名称、SSH / SFTP 来源与地址。长名称省略并保留完整提示；长地址沿用悬停滚动；菜单按钮不能被长文字挤出。颜色、间距、图标均沿用 Graphite Glass 语义 token 和现有 Icon。

## 3. 连接来源、分组与菜单

### 来源

| 配置 | SFTP 侧栏 | 默认点击 | SSH 终端入口 |
| --- | --- | --- | --- |
| 已有 SSH 配置 | 自动出现，标为 SSH | 打开 SFTP | 聚焦同一配置的已有可用终端，否则新建 |
| 独立 SFTP 配置 | 保存后出现，标为 SFTP | 打开 SFTP | 用户主动点击后尝试打开 SSH 终端 |
| RDP、S3、JumpServer 平台 | 首版不列入 | — | — |

「列出」仅表示可尝试连接的配置，不表示已检测服务器支持 SFTP。打开侧栏时不批量联网、不弹出认证或主机密钥提示；实际打开时再处理认证、主机密钥和子系统不可用等错误。JumpServer 的文件传输需要专门适配，不从普通 SSH 直连能力推断。

### 分组和搜索

- 来源筛选：全部 / 来自 SSH / 独立 SFTP。
- 显示方式：目录树 / 标签分组 / 平铺列表，默认目录树。
- 目录与标签复用连接管理的字段、路径规范和重命名逻辑。来自 SSH 的条目是同一配置的另一种视图，修改名称、目录或标签会同步到连接管理，不创建副本。
- 标签组显示所有带该标签的连接，同一连接可以出现在多个标签组；无标签连接放在「无标签」。标签图标与目录图标保持区分。
- 搜索名称、主机、用户、目录和标签；匹配目录或标签时直接显示相应连接，保留打开 SFTP / 打开 SSH / 编辑入口。⌘K / Ctrl+K 同步支持独立 SFTP 配置。
- 各组按名称自然排序，同名用稳定 ID 决定次序；点击连接不改变位置。目录、标签重命名继续使用原有事务机制。

### 连接行操作

单击直接打开 SFTP；悬停显示更多菜单，右键与键盘菜单键也能打开：

1. 打开 SFTP。
2. 打开 SSH 终端。
3. 编辑连接；SSH 来源明确显示「编辑 SSH 配置」。
4. 克隆连接，沿用现有名称后缀和后端凭据继承机制。
5. 删除连接，确认框说明将删除共享配置，不是只从 SFTP 侧栏移除。

首版不额外提供「隐藏某个 SSH 条目」或 SFTP 专属的目录 / 标签覆盖层，避免两套分组含义不一致。如确需不同的认证、目录或标签，可显式新建独立 SFTP 配置；不能悄悄复制来自 SSH 的条目。

## 4. 新建 SFTP 与打开 SSH

「＋」打开新建 SFTP 弹窗，字段包含名称、主机、端口（默认 22）、用户名、密码 / 私钥、网络代理、目录、标签和描述。复用已有认证表单、校验和凭据处理，不增加收藏选项。

- 在目录中发起新建：预填当前目录。
- 在标签组中新建：预填当前标签。
- 保存后创建独立 ID，类型为 SFTP；取消不创建配置。
- 保存后默认保留在列表中，不自动建立连接；用户明确选择打开时才发起连接。
- 连接管理新增可用的 SFTP 类型筛选、卡片标识与新建入口。

「打开 SSH 终端」的含义是打开另一种通道，不是把文件传输配置永久改成 SSH：

1. 有同一配置的已连接终端时，优先聚焦当前匹配终端，否则聚焦另一个匹配终端。
2. 没有可复用终端时，使用同一 profile ID、认证方式和代理路由申请 SSH shell 通道。
3. 保持当前 SFTP 标签、路径和传输任务不变；关闭其中一个通道不连带关闭另一个。
4. 仅允许 SFTP 的账号可能被服务器禁止 shell。此时提示「该账号不允许打开 SSH 终端，SFTP 可继续使用」，不反复重试，不修改服务器权限。
5. 侧栏的打开终端操作只负责打开 / 聚焦终端，不自动执行 `cd`。文件浏览器里的「在终端打开目录」继续使用现有同主机匹配和路径转义规则。

若将来需要永久修改默认打开方式，应在编辑器中明确修改「连接类型」，与「打开 SSH 终端」分开设计，不在本轮引入隐式转换。

## 5. 数据与实现边界

### 当前基础

- `app/ActivityBar.tsx` 目前包含会话、连接管理和 S3，需要新增 SFTP Activity。
- `ssh/connectionTypes.ts` 已预留 SFTP 选项，但当前不可用，且保存的 SSH DTO 未区分 SSH / SFTP。
- `app/App.tsx` 的打开 SFTP 路径已经不创建终端，文件操作按 profile ID 读取配置。
- `app/sftpTerminal.ts` 已按配置 ID 查找匹配终端，可复用并补充“没有终端则新建”的分支。
- SFTP 标签已支持保持挂载、目录状态、传输任务与跨窗口工作区；新入口必须复用这些机制。

### 推荐数据方案

扩展现有 SSH 传输配置，新增受约束的 `connectionType: "ssh" | "sftp"` 字段，旧数据默认 `ssh`。该字段决定显示分类与默认打开动作，认证、profile ID、目录、标签及代理仍复用原有存储与仓库。

这样独立 SFTP 配置在产品上是独立类型，在传输层可以直接使用现有 SFTP 命令和 `SshConnectionPool`。无需维护第二套凭据副本或绕过连接池。SQLite 增加编号迁移，同步 Rust serde 默认值、请求 DTO、TypeScript 类型、服务封装、编辑草稿和导入导出；旧 YAML / 旧数据库缺少字段时兼容为 SSH，未知类型明确报错。

普通打开连接的处理器应基于配置类型分派；“打开 SSH 终端”走显式终端入口，避免 SFTP 类型被默认分派再次带回文件管理。后端不要依据分类字段推断服务器一定允许 shell。

### 主要改动

| 范围 | 工作 |
| --- | --- |
| 导航与设置 | ActivityId、默认导航配置、已有偏好升级、展开 / 折叠、快捷命令 |
| SFTP 连接侧栏 | 新增组件，复用目录树 / 标签 / 搜索与行菜单 |
| 连接配置 | SSH / SFTP 分类、表单、克隆、CRUD、迁移、导入导出 |
| 连接管理 | 启用 SFTP 类型，默认动作分派，显示与筛选 |
| 工作区 | 从侧栏打开时保留 SFTP 导航；终端跳转；标签去重、关闭和跨窗口归属 |
| Rust 传输层 | 继续使用共享连接池、独立子系统 / shell 通道与现有 TOFU |

密码、私钥、口令和代理凭据只由 Rust 解析；列表、日志与前端读响应不返回秘密。打开 SSH 不自动接受主机密钥变化。编辑或删除配置时沿用已有会话 / 任务保护，不能静默中断传输。

## 6. 实施顺序与验收

建议按三个阶段实施，属于同一个功能的完整交付：

1. **入口与复用**：新增侧栏，列出现有 SSH 配置，实现分组标签、打开 SFTP、导航保留及 SSH 终端跳转。
2. **独立配置**：完成 SQLite / DTO 的类型字段、SFTP 编辑器、连接管理、克隆和导入导出联动。
3. **回归与验收**：覆盖升级、认证、工作区与错误分支，最后做深浅主题和窄侧栏视觉检查。

验收重点：

- 打开侧栏不联网；RDP / S3 / JumpServer 不混入普通 SFTP 列表。
- 旧 SSH 配置无损升级；新建 SFTP 可保存、编辑、克隆、删除和导入导出。
- SSH 来源的分组标签在两个入口同步；目录根节点、嵌套路径及标签重命名正确。
- 点击条目只开 SFTP，不产生终端；重复点击聚焦既有文件标签。
- 打开 SSH 正确复用同配置终端或创建新终端，不跳到其他主机或本地 shell。
- SFTP-only 账号拒绝 shell 后，文件浏览和传输仍正常。
- SFTP / SSH 两个通道分别关闭；切换导航、锁屏、标签移窗遵循已有生命周期。
- 长名称、长地址、无连接、无搜索结果、236px 窄侧栏及深浅主题均可用，操作按钮不被挤出。
- 前端类型检查 / 构建、相关回归，以及 Rust fmt / clippy / test 通过；真实服务器验证密码、私钥、代理、首次主机信任和仅 SFTP 权限场景。

首版暂不扩展 FTP / FTPS / SCP、多跳、JumpServer SFTP、后台批量探测或连接副本的独立分组覆盖层。

## 7. 首版实施结果与待验收

已接入 SFTP 活动入口和可配置导航显隐，旧偏好一次性补入新入口；侧栏支持目录 / 标签 / 平铺、来源筛选、模糊搜索、分组内新建、目录 / 标签重命名和连接菜单。SSH 与独立 SFTP 复用配置仓库、认证、连接池和现有文件工作区。SFTP 默认动作、克隆、连接管理、最近连接、快捷命令与 YAML 导入导出已联动；迁移 013 为旧记录补默认 SSH 类型。导出同时保存代理设置，预览继续脱敏，导入拒绝脱敏凭据占位符。

文件管理新增“打开 SSH 终端”，优先聚焦同配置已有可用终端，未找到则显式创建终端；SFTP 标签保持打开。删除共享配置时说明影响范围，并要求先关闭该配置的 SFTP 标签，避免中断文件操作。

本地验证：旧数据库重复升级、SSH/SFTP 类型 CRUD / 克隆、未知类型拒绝、YAML 类型及代理往返和秘密脱敏；前端覆盖混合来源、名称稳定排序、目录标签模糊匹配、独立 SFTP 默认动作及导航偏好升级；隔离浏览器验证新建默认类型、目录 / 标签预填、菜单、来源筛选、无搜索结果、深浅主题和 220px 侧栏。

待验收：真实 SSH/SFTP 服务器的密码 / 私钥 / 代理、TOFU 提示、仅 SFTP 账号拒绝 shell 后的错误表现和传输持续性、长任务跨窗口及 Windows/macOS 原生工作区。当前复用原有通道错误呈现，尚未增加针对特定服务器权限错误文本的自动分类。

侧栏视觉补充：标题提供带文字的新建按钮，搜索框支持清除按钮和 Esc 清除；选中连接使用窄边标记，悬停 / 键盘聚焦 / 选中时显示 SSH 终端与更多操作，来源标识让位给操作区但不引起布局跳动。220px 侧栏、深浅主题、快捷终端按钮、键盘操作和分组切换已用隔离示例验证。
