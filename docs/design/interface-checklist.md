# 界面重设计方向：柔和几何与整体配色

> 当前界面方向与强制执行清单；所有界面改动均须遵守。
> [迁移记录（2026-11-21）](../history/documentation-migration-map-2026-11-21.md)；保留原文时间与验收限定语。


## 目标

- 整体更精致、柔和、有层次，减少大块平直矩形拼接和沉闷的冷黑底色。
- 保留 SSH 管理器的专业效率：连接状态清楚，终端与文件内容优先，常用动作易发现，键盘操作完整。
- 支持**整个应用的配色**自定义。它改变背景、表面、边界、文字层级、焦点和主操作的配色关系；深色 / 浅色 / 跟随系统仍是独立维度。

## 布局与形状

- 保留工作台的主要导航和功能关系，但允许重新组织页面内部布局、间距与视觉层级；不把现有 `48px` 活动栏、`36px` 标签条等尺寸视为永久标准。
- 页面底板、侧栏、标签条、工具栏、表单区和浮层采用一致的柔和曲线。先定义语义半径层级，再按控件尺寸与嵌套关系使用；内层半径应小于外层，留出均匀的内边距。不要把所有东西做成同一种胶囊形。
- 使用留白、表面明度和少量边界建立分组。减少“一个功能一个矩形框”的卡片堆叠；连接列表、树和表格仍可保持紧凑、易扫描。
- 顶部导航、活动状态、侧栏选中态、按钮与输入框应共享形状语言。标签与分屏边界须清楚，圆角不能截断焦点环、滚动条或内容。
- 大窗口可通过更宽的边距与分栏增加呼吸感；窄窗口优先保留操作和信息顺序，不靠挤小字号维持布局。
- 避免不必要的辅助标签和说明，让分组、对齐、控件名称与状态本身发挥解释作用。只保留会影响操作判断、安全或结果的提示；不要用段落重复标题、按钮或选项已经说清的内容。

## 强制执行：每次界面改动

本节适用于新增页面、功能扩展和局部修复。每次修改界面都必须遵守，不能因改动小或沿用旧实现而跳过；所有编辑器及编码代理统一从 [`AGENTS.md`](../../AGENTS.md) 读取要求，日常设计规则见 [`docs/design.md`](../design.md)。

- **统一视觉**：复用现有语义颜色、间距、圆角、尺寸和过渡 token；保持柔和矿物底色、克制的海玻璃强调色和协调的内外圆角。浅色、深色与自定义应用颜色都应成立，不用硬编码色值另做一套风格。玻璃只用于稳定导航与浮层，不给终端正文和滚动内容叠加模糊。
- **统一控件**：布尔项用 `SettingsSwitch`，少量短互斥选项用 `SegmentedControl`，较多选项用共享选择菜单；确认和输入弹窗复用 `Dialog`。相似操作使用相同符号、尺寸与交互，不新增系统原生 `alert` / `confirm` / `prompt`。
- **设置行对齐**：标签与操作沿同一基线排列；数值和单位合成一个圆角输入控件，恢复默认放在分组标题右侧。常用数值可提供分段预设，同时保留精确自定义输入。分组靠留白和轻分隔表达，避免给每个设置叠加独立卡片或装饰图标。
- **文案克制**：让布局、标签和选中状态解释功能，默认不添加常驻小字说明。常规机制、默认值和键盘操作不需要在控件下反复解释，例如“超出行数时自动移除最早的输出”应省略，也不要改成另一句提示继续占位。仅在实际发生输入错误、操作失败或需要确认不可逆风险时呈现必要信息；取值范围通过控件约束表达。
- **交互完整**：保留原有取值边界、默认值、本机保存和跨窗口同步；支持键盘操作、清晰焦点、禁用与错误状态。输入错误应在原位置提示并保留输入，不能把排版优化变成静默修改配置。
- **交付检查**：按本次改动范围检查宽窄布局、深浅及自定义配色、键盘焦点和相关状态；运行类型检查与生产构建。验证记录须区分组件 / 模拟检查和原生实机观察，未验证的部分如实说明。

## 配色模型

- 当前以柔和的矿物灰、海玻璃绿与少量暖色细节作为基线。后续方案继续保持中性、低噪声、有温度的底色，并用少量协调的色相营造辨识度；避免整屏近黑、灰泥感、大面积高饱和或俗艳渐变。
- 当前主题模型有三个彼此独立的轴：`appearance = light | dark | system`、`appPaletteColor = 自定义 RGB 或默认海玻璃绿`、`terminalScheme = 终端方案 ID`。自定义应用颜色在本机保存，深浅外观共用同一色相但分别生成可读的语义 token；未来若加入多套命名预设，沿用这套 token 边界。
- 每套应用配色提供深浅两组语义 token：画布、导航、普通 / 凹陷 / 浮起表面、文字层级、边界、交互强调、选中、焦点、主按钮、玻璃 tint 与不透明 fallback。成功 / 警告 / 错误仍保持可识别的业务语义。
- 色板允许输入任意 RGB 颜色，所选颜色的色相与明度共同影响工作区表面和强调色；生成时约束饱和度与按钮对比度。默认海玻璃绿保持现有视觉基线。色彩语义状态（成功 / 警告 / 错误）保持独立。
- 组件只引用语义 token；禁止在页面内按配色 ID 写局部覆盖。切换配色时，主窗口、独立窗口、设置、菜单、弹窗和 Monaco 外壳同步更新；终端内容色由终端方案控制。

## 玻璃与层次

- 应用内轻玻璃可用于稳定的导航 chrome、命令面板、菜单和少量浮层。用透明度、适度模糊、柔和边缘与背景 tint 建立层次，不追求夸张折射、强高光或连续动效。
- 终端、Monaco 正文、远程桌面、长列表 / 树 / 表格与高频滚动区保持不透明或近不透明。浮层文字必须在实际合成背景上可读。
- 减少透明度、系统高对比或不支持 `backdrop-filter` 时使用实色表面；原生窗口透出桌面的可选能力仍按 [`liquid-glass.md`](../../openspec/changes/native-window-material/design.md) 单独评估。

## 交互与验收

- 用文字、图标、形状或位置共同表达连接、错误、禁用和选中状态；焦点清晰，键盘导航和屏幕阅读器名称完整。
- 正文与重要控件按 WCAG 2.2 AA 对比度检查；半透明表面按最不利的实际合成结果检查。保留终端 WebGL 选区的特殊校准约束。
- 动效只服务于状态变化。玻璃和配色切换不得带来终端滚动、窗口缩放和分屏的可感知性能回退。
- 每个重设计页面至少检查：深色 / 浅色、不同应用配色、窄 / 宽窗口、主 / 独立窗口、减少透明度与键盘焦点。先做页面级视觉验证，再扩展到全应用一致性。

## 与既有文档的关系

- [`docs/design.md`](../design.md) 是适用于所有编辑器与编码代理的日常 UI 实施规则；[需求索引](../requirements.md)提供当前行为规格入口，后续需求按 [OpenSpec 流程](../openspec-workflow.md)管理。
- [`graphite-glass-theme.md`](../history/graphite-glass-theme.md) 与 [`graphite-glass-theme-tasks.md`](../history/graphite-glass-theme-tasks.md) 记录上一轮主题实施、色值和验收，不再约束未来页面必须保持冷黑 / 冰蓝或小圆角。

## 参考依据

- [Appica UI — Toolbar](https://appica.dev/ui/components/react/toolbar)：组合按钮、输入与选项，保持一致交互。
- [Semi Design — Layout](https://semi.design/en-US/basic/layout)：组织 Header、Sider 与 Content，并按可用空间调整导航。
- [21st.dev](https://21st.dev/)：导航、主题和交互组件的设计参考。

- [Apple Human Interface Guidelines — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)：将玻璃用于导航与控制层，内容层优先保持清晰，并考虑可读性与透明度设置。
- [Apple Human Interface Guidelines — Color](https://developer.apple.com/design/human-interface-guidelines/color)：颜色要在不同外观和对比度环境下成立，状态不能只靠颜色传达。
- [Microsoft Windows 11 Geometry](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/geometry)：递进的圆角、嵌套元素和一致的间距形成柔和、连贯的界面。
- [Microsoft Fluent 2 Design Tokens](https://fluent2.microsoft.design/design-tokens/)：以语义 token 管理颜色、间距、圆角等，支撑系统性换肤。
- [Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)：桌面背景材质应服务于层级与性能，不能靠透明效果承担全部视觉设计。

> 当前需求在 OpenSpec，页面实施与验收进度在 [验证记录](../verification/interface-redesign.md)，不在本清单维护。
