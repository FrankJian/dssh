## 行为

### 已显示历史的可回看行数

“设置 → 终端 → 显示与配色 → 输出历史”支持每终端 0～100,000 行滚动历史，默认 **2,000 行**，参考 [PuTTY 官方默认值](https://the.earth.li/~sgtatham/putty/0.85/htmldoc/Chapter3.html#using-scrollback)。按显示行计算（包括自动换行），不包含当前屏幕；0 表示只保留当前屏幕。

已经显示的最早行在超限时由 xterm 自动淘汰，普通历史淘汰不暂停命令、不重置终端，也不等待用户恢复。缩小上限立即释放多余历史，调大不重新加载已淘汰行。设置保存在本机 localStorage，新建终端读取当前值，已有实例与同源独立窗口通过偏好订阅同步更新，保持当前屏幕和 alternate screen。

这控制可向上滚动的渲染历史，不是完整日志文件、后端 AI/冷启动原始历史缓存或待解析队列的大小，也不是敏感文本的安全擦除。以下消费确认和过载保护继续约束尚未显示的数据，不能用丢弃任意未解析 ANSI 字节替代历史淘汰。

### 尚未解析的数据

普通持续日志按原顺序显示。前端在 xterm 的 `write(data, callback)` 完成解析后确认消费位置；后端只向该视图投递有限的未确认数据，额外积压留在有界后端队列。没有实例的视图在完成自身有界历史/追踪器处理后确认，后续首次挂载仍只重放保留历史。

输出长期快于消费者时，不能同时保证有限存储、保留全部日志、又不限制生产者。当前选择明确暂停该视图：清理未发送队列、停止向它发送后续输出，屏幕保留已投递前缀；显示常驻提示“部分输出未显示”。任务继续运行，输入、关闭和其他 SSH channel 不因等待 UI 而暂停。不会截掉若干 ANSI 字节后悄悄继续同一个解析流。

用户可按 Ctrl+C 停止任务，或点击“清屏并显示最近输出”。后者明确放弃未显示积压，建立新订阅，按原有上限读取最近 200,000 UTF-8 字节；以 CAN + RIS 在原写入队列之后重置显示，抑制历史查询回复，等待快照解析完成后才消费新实时数据，再将焦点交回终端。它不是任意 TUI 的完整屏幕恢复；全屏程序可能需手动刷新，完整屏幕移窗仍是单独的后续项。

## 上限与隔离

| 项目 | 每会话、每订阅窗口的限制 |
| --- | --- |
| 单次输出载荷 | 最多 16 KiB UTF-8 原始数据，沿有效字符边界分片 |
| 未确认输出 | 最多 128 KiB，且最多 16 个输出包 |
| 后端等待队列 | 最多 4 MiB，且最多 512 个等待事件 |
| 过载提示 | 同一订阅一次；显式恢复生成新 token |

这里的字节数指原始 UTF-8 文本，并非 JSON 编码后 IPC 大小、JS 字符串物理占用或整个应用的 RSS。内存上限按订阅数增长，不按运行时长或累计输出量增长。既有 Rust/前端历史、xterm 滚动区的上限保持各自语义；初始历史与少量本地提示也不属于实时输出窗口。

后端 ACK 按调用 WebView 和订阅 token 校验，只接受实际已发送包的边界；陈旧/已关闭订阅确认不影响新视图，伪造未来位置或字符中间位置不能释放额度。前端累计确认连续完成的输出，合并在途 ACK；解析失败不确认丢失字节，并退订/报告错误。

连接状态与输出正常情况下仍按同一队列排序；暂停后低频生命周期通知继续送达，不释放输出额度。后端没有等待 ACK 的同步阻塞、没有暂停 SSH channel 读取、没有更改连接池/TOFU、没有向远端注入 XON/XOFF 或自动发送 kill。输入走原 SessionCommand 队列；历史解析期间也允许用户的 `0x03`，继续抑制历史产生的设备查询回复。
