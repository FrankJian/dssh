## 结论与范围

审阅终端从 Rust PTY/SSH、IPC、历史缓冲到 xterm 的路径、重连、分屏/移窗生命周期，以及连接库、配置导入导出、本地 SFTP、主机工具轮询、AI 后台会话和主要工作台布局。这里区分源码确定的问题、已修复的问题和需要实际设备才能确认的现象。没有 Windows 客户端、问题主机和故障转储，不能据此宣称已复现或消除用户报告的全部卡死。

现有代码已经实现输出合并、常驻 xterm、仅可见实例使用 WebGL、ConPTY 提示和拖拽期间暂停 fit；旧终端性能文档的现状表不再完全代表当前实现。不要重复实现它们，也不要恢复“暂停一个 SSH channel 的消费”作为反压：现有 russh 的投递可能阻塞共享 transport，连累 SFTP 和转发。

## 已落地修复

| 问题 | 触发及影响 | 改动 |
| --- | --- | --- |
| 配置导入导出同步执行 Argon2、YAML 和 DB 操作 | 加解密、大配置导入期间窗口线程被占用 | 在 blocking worker 执行，保留原 AppError 与返回协议 |
| 本地文件读写/图片编码同步执行 | 慢磁盘或网络路径使窗口不响应 | 文本用 Tokio 文件 API；图片读取及 Base64 在 blocking worker 执行 |
| SSH 连接库/凭据库同步 DB 和私钥文件操作 | 数据库锁等待或私钥位于慢路径时阻塞窗口 | 11 个连接库命令改为异步响应，DB/文件操作放 blocking worker；保留已有访问检查 |
| Windows 逐个 metadata 探测 A–Z | 断开的映射网络盘可能等到超时 | GetLogicalDrives 读取盘符位图，不打开磁盘；离线盘仍可显示，用户选择后才访问 |
| 历史缓冲反复 Array.shift | 大量小块输出时反复移动整个数组 | 用 head 索引逐块释放、批量整理；读取历史不再合并并改变淘汰粒度 |
| 自动重连保留旧 PTY 的隐藏光标/TUI/输入模式 | 新 shell 继承旧应用的隐藏光标、鼠标/粘贴报告或同步绘制模式 | 在 offline 和 reconnecting 边界结束旧模式并显示光标；CAN 终止未完整的 CSI/OSC，保留屏幕历史 |
| 登录脚本/远端程序自行隐藏光标 | 连接仍正常，但没有可见光标 | 会话工具增加“恢复终端光标”，仅修复本地显示，不向远端发送命令，不自动覆盖正在运行程序的光标语义 |
| 分屏拖拽丢失 mouseup | 失焦/卸载后 fit 始终暂停，鼠标形状未恢复 | blur、卸载和新拖拽前都清理，结束动作幂等；忽略非主键及零尺寸拖拽 |
| 分屏只能用鼠标调整 | 键盘不能聚焦/操作 separator | 添加名称、当前百分比、方向键/Home/End、Shift 大步调整和焦点状态 |
| AI 后台会话轮询重叠 | 请求慢于 2 秒时累积并发/旧结果 | 同一会话仅一个查询在途，成功清除旧错误 |

### 后续轮次：跨窗口输出与状态交接

- 后端按会话/窗口保存订阅，注册和历史快照在同一锁边界返回累计 UTF-8 字节序号。前端只处理自身订阅的会话，早到数据先暂存，再按序号接续快照；忘记/关闭的会话不能因迟到数据重新建立缓存。
- 使用绑定调用 WebView 的 **typed JSON IPC Channel**，没有切换到原始字节通道、没有改变 UTF-8 解码或连接池。在当前 Tauri 2.11.5 的 `event/listener.rs::emit_js_filter` 中，定向事件仍向其他已注册该事件的 WebView eval 载荷脚本（即使匹配 listener id 为空）；只改 emit_to/过滤回调无法消除这部分开销，独立 Channel 避开该路径。
- 输出和连接状态放在同一个有序 Channel，发送时共享 delivery 锁，避免大载荷异步取数导致断线/reset 先于最后一段 PTY 输出。全局低频状态事件保留兼容，工作台不再订阅它。AI 已发送输入的低频观察事件仍全局广播，但前端在分配任何 tracker 前过滤自身订阅。
- 订阅标识区分同一窗口的新旧视图，旧取消不能移除新订阅；关闭原生窗口同步清理，取消尚未返回的注册会在响应结束后补退订。后台 AI 会话接管前不能订阅。
- 实机发现自定义 zsh prompt 在移窗后被历史形状启发式误判为运行中。移窗描述现在携带源窗口已知的活动会话列表，已知空列表与旧描述的“未知”状态分开；OSC 133 的新状态优先于移窗提示。该信息仅存在进程内工作区，不写数据库。新版 macOS QA 原生包已复验：空闲终端移窗不误报，运行中的 sleep 任务移窗后仍触发关闭确认；确认后只结束其所属会话，测试应用已退出。
- Rust 回归覆盖订阅检查点、目标消费者隔离、陈旧取消、窗口清理、输出/状态顺序、接管前隔离和 worker 重启保留 stream；前端覆盖早到输出、Unicode 字节序号、重复事件、取消/重新挂载、关闭和序号缺口报错。

### 后续轮次：检查点续接与缺口拒绝

- 订阅命令增加可选 `afterOffset`，响应明确携带 `startOffset` / `endOffset`。不指定时仍读取保留历史；指定时必须返回检查点之后的完整 UTF-8 字节后缀，不能用当前历史尾部代替丢失的输出。
- 历史已淘汰、位置超前或落在 UTF-8 字符内部时返回 `terminal_output_gap`，验证在替换订阅之前完成。集成回归确认：同窗口失败注册不会撤掉原订阅，原窗口继续收完整实时输出；有效检查点可以位于 ANSI 跨块之间，后续字节保持原样。
- 前端在应用任何快照前校验会话、字节长度及起止序号，检查点附件不能试探性地断开已有视图。新增回归覆盖 Unicode、早到输出、错误/缩水响应和保留原连接。
- **这是输出续接基础，尚未启用 App 的屏幕快照移窗。** 现有移窗路径仍使用冷历史。xterm 已解析位置的检查点、ANSI 解析状态、窗口就绪及失败回退仍待实现；新增参数不构成任意 TUI 恢复保证，也没有给 IPC/xterm 待处理队列设置上限。

### 后续轮次：刷屏解析与 Rust 历史保留

- Rust 原始历史改为分块双端队列，小消息合入 4 KB 页，淘汰只移动块首偏移；超过上限的单个输入只复制其保留尾部，避免保留超大 backing allocation。对外仍返回同样的 String 和 200,000 字节/UTF-8 边界语义，历史并未变成完整屏幕快照。
- 命令活动和目标地址追踪器按连续文本段处理，分别保留行尾/行首；CSI/OSC 跨包解析与 Unicode 行边界保持原语义。命令追踪器的 Tab 洪水也受行长度上限约束。目标追踪器避免对没有 @ 的普通日志行运行 shell prompt 正则。
- 原始输出快照增加内部版本。即使刷屏淘汰后恰巧留下完全相同的文本，确认期间有新输出也会使旧 AI 输入审批失效；版本不下发给前端、不改变显式审批流程。

### 后续轮次：其余窗口线程阻塞

- 锁屏的全部 6 个入口转为 blocking worker，包括看似轻量的状态读取和活跃计时：它们也可能等在密码校验持有的状态锁后。设置/锁定/解锁/超时锁定仍在原 `RdpManager::update_app_lock` 操作内完成状态变更与显隐，未拆开互锁。原实现 `set_locked_inner` 最多等待原生确认 8 秒，这种等待此前可能发生在窗口线程；这是代码可确认的卡顿风险，尚不是用户实际故障的根因证明。
- AI 模型配置、会话列表/创建/保存、后台会话读取/接管和发起运行共 9 个同步入口后台化。窗口归属检查和运行保留逻辑仍在同一操作内；前端已有逐会话保存 Promise 链，继续按序保存，不把旧快照并发覆盖到新快照上。
- S3 配置/书签的 8 个入口、SMB 配置的 3 个入口和 JumpServer 的列表/身份/打开网关/打开终端共 4 个入口后台化。既有访问检查与 S3 客户端失效顺序保留；并未改动远端协议或凭据下发边界。
- `start_ssh_session` 的配置解析与数据库读取也移到 blocking worker，再由既有 SessionManager/连接池启动 SSH；没有新增连接路径或改变 TOFU。
- 这些命令继续返回同样的 DTO/AppError，前端原本就是等待 Promise，无需改变操作步骤。当前原生交互工具不可用，31 个入口的本轮线程调整尚未做新的原生锁屏/设置交互复验；已有存储、归属、审批及 `lock_mutation_and_visibility_are_serialized_with_unlock` 等控制器回归通过。

## 性能证据

可复现脚本：`node --experimental-strip-types scripts/benchmark-terminal-backlog.mjs`。

同机 Node，100 万个单字符块，保留目标 200,000 字符：旧 Array.shift 约 **18,038 ms**，head 索引约 **11 ms**。这是极端小块的算法微基准，不是 SSH 吞吐、Windows UI 帧率或端到端延迟数据。实际 SSH 的合并块通常更大，收益会不同。读取历史与持续淘汰、Unicode/ANSI 内容保持、超大单块和空块有专门回归。

新增可复现微基准：

```sh
rustc --edition=2024 -O scripts/benchmark-terminal-retention.rs -o /tmp/dssh-retention-bench
/tmp/dssh-retention-bench
node --experimental-strip-types scripts/benchmark-terminal-trackers.mjs --baseline 1b0f358a0f47193cf537b188da90e5b2767d78a4
```

同机约 50 MB 合成文本的结果（单次示例，毫秒；基线 Git ref 如上）：

| 模块/场景 | 之前 | 改造后 |
| --- | ---: | ---: |
| Rust 历史追加，64 B 小块 | 2102.74 | 5.30 |
| Rust 历史追加，16 KB 块 | 8.98 | 0.71 |
| 命令活动追踪，长行 | 1676.27 | 12.41 |
| 命令活动追踪，80 列短行 | 463.77 | 27.56 |
| 目标地址追踪，长行 | 228.62 | 11.74 |
| 目标地址追踪，80 列短行 | 554.85 | 39.98 |

Rust 另测 1000 次 200 KB 快照读取：String 约 2.30 ms，分块快照约 2.39 ms（16 KB 块场景），追加优化没有把大规模工作转移到每次读取。小块通常已经由后端合并，64 B 是算法压力场景。这些数据不包含 SSH、IPC、xterm、窗口绘制或峰值内存，不能当作端到端吞吐/帧率指标。基准脚本在本机运行，不接入 CI。

光标回归直接使用项目安装的 xterm，通过 DECRQM 查询可见模式，覆盖：隐藏光标的 TUI 断线后回到原 prompt；关闭旧鼠标、焦点、粘贴及同步绘制模式；CSI/OSC 半包后的手动恢复；恢复时不退出仍在运行的 alternate screen、不删除屏幕内容。

## 未解决的性能风险（按优先级）

1. **洪水输出限流已接入，实机量化待验收。** 2026-11-21 增加消费确认、128 KiB 未确认输出窗口、4 MiB/512 事件后端队列和显式过载暂停。正常消费保持有序；超限停止该视图并提示未显示输出，用户显式清屏才接最近历史，不把残缺字节悄悄接回原解析流。真实 Windows/SSH 洪水内存与输入延迟仍需验收，详见[流控说明](../architecture/terminal-output-flow-control.md)。
2. **跨窗口输出订阅已落地，量化复测尚未完成。** 输出不再广播，迟到输出和冷启动快照已有序号交接；仍需两个独立窗口+多会话的 IPC、内存定量对照，以及 Windows 原生验收。工作区屏幕快照与截断原始历史的 TUI 恢复问题仍单列于第 4 项。
3. **Rust 历史头部搬移已消除。** 分块/4 KB 小消息页保持原读取语义；剩余读请求仍会 materialize 最多 200 KB 的 String，已补读路径微基准。需要继续观察真实 AI 频繁读取与多会话场景。
4. **冷启动/移窗历史不是完整屏幕。** 丢弃整个传输块仍可能从 ANSI 半序列开始，传输块不是协议边界；本轮修正了旧注释的错误保证。注册表已有序列化/恢复入口，但当前 App 的移窗创建请求并未携带这些快照。已补后端检查点增量订阅与缺口拒绝，完整修复仍需 xterm 写入完成检查点、ANSI 解析边界、窗口就绪确认和失败回退；仅在移窗时调用一次 serialize 仍会丢失中间输出。不能保证任意截断历史重放能还原所有 TUI。
5. **大目录和大连接库。** FilePane 仍为全部条目创建 DOM，SessionManager 标签分组存在多次 filter；千至万项列表应测量后做视口虚拟化和预计算分组。
6. **窗口线程后台化已扩展，原生复验尚未完成。** 锁屏、AI、S3/SMB/JumpServer 及 SSH 创建的上述 31 个同步入口已迁出窗口线程，保留原有互锁和访问检查。部分本来就是 async 的命令仍在 Tokio worker 中同步读取 SQLite（如 AI 连接测试/S3 客户端解析），高并发时仍需关注 runtime 占用；不能把“async”直接等同于完全非阻塞。
7. **启动 bundle。** 本机生产构建主包约 1.55 MB（gzip 436 KB），Monaco 等已有单独 chunk，但 App 的大量静态 feature import 和 useTerminalSessions→terminalRegistry→xterm 使部分 lazy 边界无效。优先测启动解析长任务，再按真实条件拆加载边界。
8. **GPU/驱动问题需 Windows 实测。** 已有 GPU 设置和 context loss 降级；本轮未收集 WebView2/GPU/驱动数据，不能把全部“无响应”归为驱动。应对比相同输出、相同窗口数、GPU 开关两组，记录 WebView2/系统版本与进程内存。

## 操作与布局审阅

- 保留“标题栏→活动栏/侧栏/标签及内容/辅助栏”的桌面结构、语义 token 和现有矿物灰/海玻璃风格；没有证据支持一次全局换色或叠加更多玻璃。终端/编辑器/文件列表保持清晰，窄窗口优先让内容有空间。
- 本轮落地的是分屏键盘操作、失焦清理和无需重连的光标恢复入口。它们直接减少用户恢复工作区的操作成本。
- 后续布局重点：长路径/长标签的溢出和完整名称可达性；窄宽度时会话动作的优先级及菜单收纳；大目录列表的紧凑详情行；设置里终端 GPU、字体、光标的清晰分组。需在实际深浅外观、主/独立窗口和 Windows DPI 下逐页验收。
- AI 后台关闭仍用 window.confirm；其他页面也有原生 alert/confirm，与应用内对话框风格和焦点行为不统一。统一时必须保留破坏性动作的明确确认。
- 主应用浏览器预览缺少原生运行环境，原生 cargo run 在当前执行环境无法连接桌面服务。另用临时隔离页面挂载真实 PaneGrid/xterm/会话菜单，实际验证了方向键 50%→52%、End→88%、隐藏后从菜单恢复可见光标，以及卸载/重新挂载后保留 prompt；临时页面已移除。随后构建独立 identifier 的 macOS QA 原生包（不读取原应用数据），完成了终端首屏、输入输出、光标恢复菜单、分屏、独立窗口继续输入，以及 5 MB/50 MB 文本输出。历史队列/解析优化后的包也在中断前观察到 50 MB 输出期间菜单可打开，随后 RETENTION_DONE_50MB 和 prompt 可见；尚未进行 Unicode 原生刷屏复验或再次确认该 QA 应用退出状态。这些不是帧率或内存有界的定量证明。**Windows 原生、多 DPI 和全部页面视觉验收仍未完成**。

## 验证与后续验收

已执行：TypeScript、生产构建、cargo fmt、clippy（all-targets 且 warnings 为错误）、Rust 全套回归；受限沙箱有 13 个本地监听权限失败，允许回环监听后的最新串行完整回归为 **228 通过、1 忽略、0 失败**（含 doc-test 阶段）。前端全量 Node 回归 **254 项通过**，包含缓冲/光标、输出订阅竞态、检查点缺口和工作区活动状态用例；Windows 盘符位图、订阅投递与旧工作区描述兼容回归通过。曾在打包和测试并行时出现 rustdoc 依赖产物冲突，打包结束后已串行复跑完整 cargo test 并通过。Windows FFI 分支尚未在 Windows 编译运行。

发布前仍需 Windows 正式包覆盖：持续洪水输出时 Ctrl-C/标签切换；本地 PowerShell 与远程 SSH 分别登录；登录脚本隐藏光标与 TUI 中断/自动重连；离线映射盘；分屏时切到其他窗口和关闭工作区；4 格分屏+2 个独立窗口；多 DPI、中文输入法及 GPU 开关。记录吞吐、最长 UI task、峰值内存、按键回显和事件率。测量方法沿用[终端性能原方案](../history/terminal-performance-plan.md)；本次微基准不能替代这些验收。
