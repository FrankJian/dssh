## 验证与边界

已通过 TypeScript / 生产构建、Rust 格式化 / Clippy / 全量测试。新增测试模拟无渲染器的同一 PTY 输入队列：IP → 资产编号 → 账号编号 → shell 命令、跨轮归属、其他对话拒绝、真实状态、接管使旧确认失效并禁止未来 AI 输入、关闭 / 接管互斥、空闲时间刷新；前端测试覆盖接管时从输出恢复命令状态。这里的模拟使用输入队列和输出缓存，不是实际 SSH 服务端端到端测试。

真实 JumpServer 账户、认证挑战、真实连接取消 / 空闲回收、后台到可见终端接管和 macOS / Windows 原生点击验收仍待完成。当前验证环境锁屏，未完成原生界面交互验收。

首版支持经典行菜单和 shell。KoKo 的[官方交互处理](https://github.com/jumpserver/koko/blob/dev/pkg/handler/interactive.go)包含经典 `Opt>` / `ReadLine` 与 PTY 尺寸处理，[资产连接实现](https://github.com/jumpserver/koko/blob/dev/pkg/handler/asset.go)在当前会话上建立目标代理；客户端是否展示窗口不影响这一连接方式。不同版本的全屏 TUI 仍需后端 VT 屏幕状态解析与受控按键能力，现有去 ANSI 的追加日志不能完整重建光标移动和擦屏后的屏幕。输出和连接状态等待已改为按会话通知驱动；输入后 / 等待新输出时，输出稳定约 120 毫秒即可提前返回，仍保留最长等待、仅回显输入保护与关闭唤醒。立即读取不进入等待。增量游标和模型流式响应仍可后续改善吞吐与首字体验。


### 2026-11-02 交互等待优化

去除了每次输入固定睡眠 2 秒、读取固定等待和后台连接每 50 毫秒轮询的额外开销。通知先注册再读取缓存，防止检查与等待之间丢失唤醒；输出分片重置稳定窗口，状态通知但输出未变不会延长稳定时间。每个会话独立通知，发送端缓存通知句柄，不在每个输出分片额外查询会话表。

提示词允许直接使用 open / write 工具返回的最新输出，避免不必要的 read_terminal 和模型往返。保留全部批准、快照 / 输入版本、认证和归属校验；返回稳定输出不代表命令成功。

模拟就绪输出用例在 10 秒等待上限下约 0.12 秒返回；这是本地等待器测试，不是厂商模型或真实 JumpServer 的端到端加速倍数。回归覆盖分片合并、静默上限、读期间通知、关闭错误与回显早于实际结果。模型请求当前仍为完整响应后展示，模型服务和推理耗时不由此优化保证。
