## 合成吞吐测量

`commandOutputFlow.test.mjs` 使用真实 xterm、现有 TerminalOutputStream 的 128 KiB ACK 窗口及四个捕获器，连续输入 64,000,000 字节无换行文本，并在仍有积压时发送 Ctrl+C。确认该候选被取消、其余三条完成输出均截断在 1 MiB，在途最大 128,000 字节，最终 ACK 消费完成。

一次本机 Node 24 运行：约 967 ms；单包捕获处理峰值 0.28 ms；每 64 包采样的堆增量峰值 7,910,432 字节、RSS 增量峰值 20,987,904 字节，结束时堆增量 3,631,400 字节。测量包含 xterm 与测试分配，未强制 GC，采样峰值不是绝对峰值，也不是应用 RSS 上限。批量普通文本路径显著降低了逐字符处理的分配和停顿。

尚未测量真实原生工作区中打开菜单/预览/弹窗时的持续洪水、移窗期间内存峰值和多连接长稳表现。

## 2026-11-22 普通 SSH 启用入口补齐

问题复现：同一 `ll` 输出，在无标记时为 0 条，提供完整标记时为 1 条；原版本没有主动启用路径，不能在未配置的普通 SSH 中直接工作。本次增加了用户确认后才发送的会话内 Bash/Zsh hook。

`src/terminal/shellIntegration.test.mjs` 使用 `scripts/test-shell-integration.py` 创建真实隔离 PTY，关闭用户 rc 文件并将 HISTFILE 指向空设备，以临时目录中的 `example.txt` 验证 `ll` 别名、失败命令、原 hook 输出、原提示符、退出状态和重复安装；另验证冲突及选错 shell 不安装。当前实测本机 Bash 3.2、Zsh 5.9，未使用用户的 SSH 服务器，不将本机 PTY 等同于真实 SSH 验收。Windows 上 PTY 夹具显式跳过；缺少 Zsh 的主机同样显式跳过对应项。

真实 PTY 暴露并修正了 Zsh PROMPT_SP 的补齐行混入输出问题；结束标记现置于该清理之前。新增 Rust 回归覆盖脚本单行大小、认证/菜单/全屏提示排除、非活动/本地/私有会话拒绝、过期批准不入队及归属锁保护。启用 UI 使用独立的本机模拟服务验证准备只读、取消零发送、选择 shell、确认一次发送、失败原位反馈、超时和焦点恢复；浏览器观察与后端/PTY 测试分别记录，不合并宣称真实 SSH 端到端通过。

本轮最终结果：109 项终端回归全部通过，Rust 235 通过、1 项既有忽略；类型检查、生产构建、格式、严格 Clippy 和全量 OpenSpec 严格校验通过。重连回归确认旧回放标记不能宣称新 shell 已启用。锁屏/归属校验入口已按调用路径审查，实际原生锁屏与移窗期间操作仍随原生验收任务复验。

## 2026-11-22 macOS 原生与授权 SSH 复验

使用当前源码构建独立标识 `com.dssh.command-output-qa` 的 macOS 调试应用，以真实本地 PTY 启动不读取用户 rc 的 Zsh，手动加载仓库临时 hook 后执行两行 `printf`。实际观察到完成记录、正确的详情正文及复制成功反馈；本地测试 shell 均正常退出。此操作是验收夹具，不表示本地终端已有产品内的启用入口。

原生鼠标操作暴露了 WebKit 点击按钮不自动聚焦时，关闭详情会将焦点返回页面根部的问题。命令行现先显式聚焦再打开 Dialog；重新构建原生包后，实际复验 Escape 返回原命令行，下一次 Escape 返回魔法工具入口。

经用户明确授权，更新既有 Design QA 应用为当前源码，并使用其中的 `aliyun` 普通 SSH 连接。未读取或复制凭据，未修改远端配置文件。实际通过产品入口选择 Bash 并确认安装，观察状态转为“已启用”；重新执行 `ll` 后列表出现记录，详情包含目录输出且不带提示符或命令回显。安装脚本本身没有记录。

随后执行两次相同的 `printf`，中间执行输出测试错误文本并返回失败的命令：列表按新到旧显示四次执行，重复命令独立保留，失败输出可查看。原生详情复制返回成功；行尾直接复制没有打开详情。将系统剪贴板粘贴到应用的连接搜索框，观察值仅为测试输出正文（单行输入框将换行归一化为空格），没有命令、提示符或时间；核对后已清空搜索。

在会话工具中重新连接后，原记录消失，状态恢复“尚未启用命令识别”，没有自动重新安装 hook。最后关闭本轮创建的 SSH 标签，应用显示“暂无活动会话”。本轮未进行远端文件写入或破坏性操作。

修正后类型检查、生产构建与两个 macOS 调试包构建通过；命令输出模块 18 项测试通过。尚未覆盖真实 SSH 的认证交互、自定义提示符组合、JumpServer、Windows、原生洪水性能和完整配色/独立窗口矩阵，任务 3.5、4.2～4.4 保持未勾选。

## 2026-11-22 Windows CI 换行回归修复

用户提供的 Windows GitHub Actions 日志显示，内置脚本的单行输入断言检测到多个裸回车。原编码只转义 LF，Windows 以 CRLF 检出脚本时会残留 CR。编码现先将 CRLF 归一化为 LF，再转义独立 CR；同时用仓库 Git 属性固定两份集成脚本为 LF 检出，保持既有单行输入契约。

新增回归使用两份真实脚本显式构造 CRLF 文本，确认编码结果与 LF 完全相同、输入小于 3900 字节且只有结尾一个控制字符 CR；另覆盖独立 CR 的转义。macOS 本机 shell 集成 4 项测试及完整 Rust 测试通过（237 通过、1 项既有忽略），格式、严格 Clippy 和差异空白检查通过。未在本轮重新运行 Windows GitHub Actions；CRLF 回归不依赖本机检出换行格式。
