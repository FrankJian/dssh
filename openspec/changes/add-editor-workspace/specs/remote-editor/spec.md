# 文本编辑与保存增量规格

## MODIFIED Requirements

### Requirement: 编辑职责与懒加载

系统 SHALL 在首个文本读取成功或显式新建文本后按需加载本地 ESM 编辑资源及 worker，保持文件树、文本/Markdown/图片分支、标签和 TOFU；离线运行不依赖 CDN。不引入 VS Code Workbench、远端 LSP、调试器或扩展，文件操作仍由已授权文件服务承担。

#### Scenario: 打开未知扩展名
- **WHEN** SFTP 读取一个受支持大小的未知类型文本文件
- **THEN** 以 plaintext 编辑，不自动启动远端语言服务。

#### Scenario: 离线启动编辑器
- **WHEN** 无互联网环境中用户打开本地文本或新建未命名文本
- **THEN** 编辑器及所需语言 worker 从安装包加载，其他页面不因未打开编辑器而提前初始化编辑实例。

### Requirement: 模型隔离与保存保护

系统 SHALL 按文件来源、规范绝对路径和工作区实例隔离文档，同一工作区多组共享同一文档，不同实例及窗口保持独立缓冲；跟踪正文、编码、行尾的 dirty，只有显式保存才写文件。保存失败保留内容；关闭最后一个视图、切换来源或销毁前遵循保存/放弃/取消，完成后释放文档与订阅，临时切换页面不得释放。

#### Scenario: 远端保存失败
- **WHEN** 用户保存未提交文本时服务端拒绝
- **THEN** 保留文档与 dirty，展示错误，不关闭标签或虚报保存。

#### Scenario: 保存期间继续编辑
- **WHEN** 版本 A 开始保存后用户继续编辑为版本 B，随后 A 保存成功
- **THEN** 仅将 A 作为保存基线，B 仍为 dirty；后续保存串行，旧回执不能把 B 标记已保存。

#### Scenario: 跨窗口打开同路径
- **WHEN** 两个窗口独立编辑同一来源同一路径
- **THEN** 内存正文不会互相覆盖，一方保存后另一方按外部变更与版本冲突规则处理。

### Requirement: 兼容与验证范围

系统 SHALL 保留既有后端 1 GiB 文本硬上限和文件格式安全校验，使用语义主题并保持已有字体/换行等设置；新增大文件保护不得静默改变旧入口的读写契约或承诺 1 GiB 流畅交互。超过交互预算时明确提示并经选择进入受限模式或取消，不把截断正文交给保存；打包产物仍需两平台输入法、worker 与无障碍验收。

#### Scenario: 更换应用配色
- **WHEN** 用户在已打开编辑器时改变深浅或应用颜色
- **THEN** 更新编辑器语义主题并保留正文、光标和未保存状态。

#### Scenario: 文件超过交互预算
- **WHEN** 文件大小未超过 1 GiB 但超过普通编辑预算
- **THEN** 提示大文件并提供取消或关闭高成本语言/预览能力的受限模式，不静默截断、自动扫描或把部分文本保存回原文件。

## ADDED Requirements

### Requirement: 新建保存与另存为

系统 SHALL 支持未命名文档、保存、全部保存、另存为和显式重新加载；未命名文档首次保存选择来源和路径，目标存在时确认覆盖，取消不创建或截断文件。全部保存逐文档展示结果，任一失败不清除其 dirty；另存为成功才切换当前文档身份，失败保留原身份和缓冲。只读文档允许复制/另存为，禁止虚报原路径保存成功。

#### Scenario: 未命名文本取消保存
- **WHEN** 用户首次保存未命名文档后取消路径选择
- **THEN** 文档继续打开并保持正文，不创建空文件、不关闭标签。

#### Scenario: 全部保存部分失败
- **WHEN** 多个 dirty 文档中一个目标拒绝写入
- **THEN** 成功项更新保存基线，失败项保留 dirty 并可重试，汇总不显示全部成功。

### Requirement: 外部变更检测与冲突保护

系统 SHALL 在重新聚焦、手动刷新和每次保存前检查目标版本；已打开的本地文件另监测系统变更通知，远端活动文档有界轮询。外部修改不覆盖 dirty 缓冲；干净文档可自动重载并保留合理视图位置。保存发现版本变化、删除或身份变化时停止写入，提供比较、显式覆盖、另存为和取消；覆盖基于刚确认版本重验，不永久关闭检查。

#### Scenario: 外部删除后保存
- **WHEN** 打开文件在外部被删除后用户保存
- **THEN** 不静默重建原文件，保留缓冲并要求明确选择重新创建、另存为或取消。

#### Scenario: 同大小同时间戳内容变更
- **WHEN** 外部程序修改内容但文件大小和可见时间戳没有变化
- **THEN** 保存前的内容版本检查仍检测到差异，不仅凭大小/时间戳覆盖。

### Requirement: 保存失败与原文件保护

系统 SHALL 优先通过同目录临时文件写入、完成校验和受支持的替换操作保护原文件，并尽量保持权限；失败清理临时文件并报告可恢复状态。文件服务不支持安全替换或无法保持必需元数据时，默认拒绝替换并提供另存为；非原子覆盖仅在明确解释风险并经本次确认后执行。不得声称普通 SFTP 版本检查可消除所有并发写入竞态。

#### Scenario: 写入中断
- **WHEN** 临时文件写入期间断网或磁盘已满
- **THEN** 不替换原文件，保留 dirty 和失败信息；遗留临时文件可重试清理且不报告保存完成。

#### Scenario: 服务端不支持安全替换
- **WHEN** 服务端拒绝原子覆盖重命名或目标为不能安全处理的链接文件
- **THEN** 默认保留原文件，给出另存为或经过风险确认的可用降级选择，不自动回退到截断写入。

### Requirement: 编码与行尾保真

系统 SHALL 支持 UTF-8、UTF-8 BOM、UTF-16 LE/BE 与 GB18030 的重新以编码打开和以编码保存；优先识别 BOM，无 BOM 优先严格 UTF-8，失败后让用户选择而非猜测后覆盖。保留已识别编码/BOM及 LF/CRLF；混合行尾先提示规范化选择。转换不可表示字符、无效字节或未支持格式时拒绝有损保存。重新打开 dirty 文档先处理未保存决定。

#### Scenario: 非 UTF-8 文本打开
- **WHEN** 无 BOM 文件严格 UTF-8 解码失败
- **THEN** 提供编码选择，选用 GB18030 后正确打开，保存继续使用该编码，不自动插入替代字符。

#### Scenario: 转换编码或行尾
- **WHEN** 用户将 UTF-16 LE 文档改为 UTF-8 BOM 或将 CRLF 改为 LF
- **THEN** 将转换标为未保存，明确保存后才修改实际字节，失败继续保留原保存基线和 dirty。

#### Scenario: 编码文本与二进制区分
- **WHEN** 用户打开带合法 UTF-16 BOM 且包含零字节的文本
- **THEN** 按声明编码校验文本，不仅凭零字节拒绝；真实二进制或解码无效内容仍拒绝文本编辑，不绕过格式安全校验。
