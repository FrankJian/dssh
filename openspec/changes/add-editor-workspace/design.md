# Design

## Context

动机与交付范围见 [proposal.md](proposal.md)，可验收行为见 [editor-workspace](specs/editor-workspace/spec.md)、[remote-editor](specs/remote-editor/spec.md)、[workspace-layout](specs/workspace-layout/spec.md) 和 [keyboard-shortcuts](specs/keyboard-shortcuts/spec.md)。本文件描述拟实施架构，不表示功能已实现。

已检查的实现依据：

- `src/sftp/RemoteFileEditor.tsx` 已负责本地/远端读取、文件标签、保存确认、Markdown/图片分支；`MonacoRemoteEditor.tsx` 直接创建 Monaco 编辑实例，按实例命名空间管理 model。
- `src/sftp/monacoLoader.ts` 动态导入本地 Monaco、配置 ESM worker 并映射语义主题，同时被 `src/tools/CodeImageTool.tsx` 使用，迁移不能破坏该消费者。
- `src/services/sftpService.ts` 同时封装本地与远程文件操作；`src-tauri/src/commands/sftp.rs` 本地读写只支持 UTF-8，写入会直接覆盖已存在文件；`SftpManager::write_text` 使用 TRUNCATE/WRITE。现有接口没有内容版本、编码元数据或安全替换承诺。
- 现有本地与远端文本上限均为 1 GiB。现有递归搜索是文件名/相对路径搜索，并非全文搜索。
- `WorkspaceTabStrip`、`App.tsx` 和 `useWorkspace` 统一管理终端/SFTP/浏览器标签与工作台；分屏目前是终端 pane 布局。独立窗口经 Rust workspace manager 管理，不能把编辑分组当作 SSH 终端 pane。
- [工程结构](../../../docs/architecture/project-structure.md)、[设计规范](../../../docs/design.md)及[强制清单](../../../docs/design/interface-checklist.md)继续约束模块职责与 UI；VNC、原生窗口材质等活动变更不属于本次编辑器实现依赖。

## Goals / Non-Goals

**Goals:** 文档状态、文件 I/O、Monaco 视图和应用工作台分别有明确所有者；本地与远端共用编辑能力，文件授权仍在 Rust；从旧 SFTP 入口渐进迁移且保留已有行为。

**Non-Goals:** 不加载 VS Code Workbench，不新增隐式远端进程、自动保存或落盘草稿，不承诺远程全项目语义分析、操作系统崩溃后的草稿恢复或 1 GiB 文本的流畅编辑。单根目录与单文件工作区可并存，不做一个工作区内多根混合来源。

## Decisions

### 1. 独立编辑模块与可复用文档内核

新增 `src/editor/`，内部拆分工作区协调、文档注册表、分组布局、文件树/搜索、命令与 Monaco 视图。`App` 仅接入标签、活动工作台、窗口和锁屏边界，不继续堆积文件编辑逻辑。既有 `RemoteFileEditor` 作为兼容宿主逐步改用相同文档内核与视图，保留 SFTP 双栏各自独立的 workspace instance。

文件 provider 分为 local 和 sftp：前端通过 service 调用 Rust；Rust 本地文件服务使用现有文件系统逻辑，SFTP provider 只经既有 manager/共享连接池/TOFU。支持 list、stat、read、save、create、rename、copy、delete 和有界内容搜索；目录删除预览/取消、传输、属性仍复用各自已有业务。新服务集中处理 `AppError`，同步 Rust DTO、TS 类型及 camelCase 请求/事件；不把秘密或正文写入日志。

替代方案：仅给现有 SFTP 弹层增加按钮无法提供独立本地项目和分组；引入完整 VS Code 框架显著扩大运行时和权限面，因此选择独立工作台与复用内核。

### 2. 文档、视图、来源和版本身份

- 工作区：`workspaceId`、所有者窗口、来源（local 或远端授权来源 ID）、可选根目录、文档集合、分组树、活动组。
- 文档键：来源 ID + 后端规范绝对路径；未命名文档使用独立 ID。Monaco URI 额外包含窗口/工作区实例命名空间，路径分段编码，避免不同窗口、SFTP 两栏或不同远端资产同名路径串写。
- 文档：model、保存基线、当前/保存编辑版本、原始编码/BOM、原始和目标行尾、内容版本 token、权限/只读、加载/保存/冲突状态。dirty 由正文与持久化元数据相对保存基线计算，撤销回基线可清除 dirty。
- 视图：groupId + documentId，独立 cursor/selection/scroll/viewState；同工作区共享 model，model 引用计数归零且关闭决定完成后才 dispose。监听器、worker 使用与 Diff 临时 model 同样明确回收。
- 另存为成功才提交新身份，旧视图仍引用同一逻辑文档；重命名/移动按既有 SFTP 规则先处理并关闭受影响文档，成功后刷新树与路径索引，避免改变原契约。

本地规范路径由后端处理 Windows 盘符、UNC 与平台大小写语义，不在前端统一 lowercase；远端遵守 SFTP 路径大小写与来源隔离。符号链接不作为搜索递归入口，写链接必须识别真实目标与身份变化，不能用替换链接本身模拟保存。

### 3. React Monaco 与离线 ESM

新增 `@monaco-editor/react`，按需加载其 `Editor` / `DiffEditor`。先通过共享 loader 初始化本地 ESM 和 worker，再执行 `loader.config({ monaco })`，禁止退回默认 CDN/AMD。保留代码图片工具使用的 `loadMonaco` 与主题刷新契约；公共 loader 可迁入共享目录并由旧路径 re-export。

使用稳定 URI、`path`、`saveViewState` 和明确的 model 所有权；共享 model 存活期间视图卸载不 dispose，最终由注册表回收。初始化通过 defaultValue/已存在 model，不在每次 React 渲染调用 setValue，避免清空撤销历史。状态变化采用 model 事件与轻量索引，不每键复制整个多文档正文。StrictMode、懒加载取消、组件卸载与加载失败都必须可重试且无重复实例。

主题继续从应用语义 token 生成，正文和树近不透明；Monaco 语言模块/worker 按实际能力启用。实施开始锁定 wrapper 与现有 React 19、Monaco、Vite 的兼容版本，检查 pnpm peer 约束和安装包离线运行，不把官网版本号直接当作本仓库已验证结果。

替代方案：保留手写 Monaco 外壳能减少迁移，但不满足指定技术选型；默认网络 loader 会破坏离线运行。采用 React 外壳与本地 Monaco 注入。

### 4. 文件读写与安全保存协议

新增编辑器专用版本化读写契约，不悄然改变旧命令签名。读取返回规范路径、编码/BOM、行尾、权限、字节数、文本与不透明 `versionToken`。token 绑定来源、路径/文件身份和实际字节摘要，不仅是 mtime/size；编码在 Rust 统一处理，严格拒绝解码替换字符与不可表示转换。

保存请求携带预期 token、目标编码/行尾、正文快照及本次显式覆盖决定。按来源/路径串行处理同一应用内保存；先验证 token，再写同目录唯一临时文件，flush/close、校验字节与必要元数据，在提交替换前再验目标身份/版本，最后使用平台或服务器支持的安全替换能力，返回实际保存 token。未命名创建采用不覆盖创建；另存为覆盖既有目标必须带确认时版本。

本地使用平台可用的原子替换并保留权限；远端探测已用 SFTP 实现的扩展与 rename 语义，不假设标准 rename 一定能覆盖。元数据无法保留、特殊文件/链接不能安全替换或服务器能力不足时，默认阻止原路径替换并提供另存为。风险明确且协议确实支持时才允许单次确认的非原子覆盖，不能静默回到当前 TRUNCATE 方式。失败保留原文件与内存正文；临时文件清理失败单独报告，不输出正文。

保存按请求快照更新基线；等待期间继续编辑不能被旧回执清除 dirty。重试重新获取版本，不自动重放可能已完成的写入。普通 SFTP 缺少通用 compare-and-swap，检查与提交之间仍存在其他客户端写入竞态：界面不能宣称严格分布式原子性；尽量缩小窗口，遇到检测到的变化必须停止。

替代方案：沿用截断写入无法保护断网/磁盘满；只比较时间戳无法识别同大小改写；无条件锁远端文件不具跨客户端通用性。因此选择内容版本与安全替换、能力不足显式降级。

### 5. 编码、行尾与大文件预算

有 BOM 时严格识别 UTF-8 / UTF-16 LE/BE；无 BOM 首先严格 UTF-8，失败进入编码选择，可选择 GB18030 或无 BOM UTF-16。二进制签名/文本有效性检查结合编码，不能对所有零字节一律拒绝。保留原 BOM 与 LF/CRLF；混合行尾进入提示，不让 Monaco 的规范化造成无声改写。显示选项不标 dirty，转换编码/行尾会标 dirty；不添加编辑器默认尾换行或自动裁剪空格。

1 GiB 是后端拒绝上限。新工作台普通编辑预算默认 20 MiB，超过时先显示受限模式/取消；受限模式关闭语义诊断、minimap、全文格式化、Markdown 渲染和自动比较等高成本功能，绝不把截断文本用作可保存 model。接近硬上限仍可能受 WebView 内存制约，失败需可取消/恢复，不承诺成功加载。旧入口硬上限保持，能力升级不改变配置导出/保存语义。

### 6. 快捷打开、内容搜索与替换

快捷打开复用现有文件名/路径匹配与遍历边界；全文搜索另走 Rust 后台任务，以 operationId、window owner 和查询 generation 隔离。逐目录懒遍历、有限并发、有界分块读取和取消；不得在 UI 线程递归读取或经 shell 执行 grep。优先对已打开 model 搜索并标记版本，后端扫描跳过对应路径，合并后结果使用 UTF-16 行列坐标便于 Monaco 定位。

默认预算：最多 2,000 目录、100,000 项、2,000 匹配、单文件 20 MiB、扫描总量 256 MiB；达到边界报告具体截断原因。二进制、超限文件、不可解码、拒绝访问分别计数，不伪装为零结果。不跟随链接目录；默认排除 `.git`、`node_modules`、`target`、`dist`，可在本次查询调整规则。隐藏文件开关与 include/exclude 显式生效，不偷偷读取根目录以外路径。

正则统一使用浏览器 JavaScript 语义，以专用可终止 worker 对受限文件文本匹配；worker 执行超过每文件 1 秒预算则终止并报告该项超时，防止灾难性回溯阻塞 UI。Rust 仅负责受限读取/解码和文件遍历，文本经点对点有界批次返回；匹配计划同时用于预览与执行，避免两套正则引擎的语义差异。

替换计划绑定查询、路径、文档版本或磁盘 token 及前后差异；确认前不修改。已打开文件的替换作为一次可撤销 model 编辑且保持未保存；未打开文件通过安全保存协议逐项落盘，确认框明确两种结果。内容变化、权限失败或只读则跳过并报告，用户取消只停止新项目，不承诺批次原子回滚。

### 7. 命令、语言能力与布局

应用命令在现有 registry/palette 注册，作用域细分编辑正文/树/搜索/当前组，菜单、快捷键与按钮调用同一动作。默认参考 VS Code，保留现有 Command/Ctrl+K 和自定义绑定；新增 Ctrl/Command+P 快捷打开、Ctrl/Command+Shift+P 命令搜索仅在不冲突时分配。Monaco 原生动作通过编辑器适配器调用，禁止重复派发；关闭文件与关闭工作台使用不同 action ID。

语言高亮与基础语法能力按 provider 实际能力映射，JS/TS、JSON、HTML/CSS 等利用本地 worker；可用的悬浮、跳转、重命名、格式化才显示启用。Python/Go/Rust 不因此获得远端语义服务。问题面板只汇总当前实例已加载 model 的 markers，切换文档不能混入其他窗口诊断。

编辑工作台内部使用独立分组树，与终端 pane tree 分离；Explorer/搜索为左侧内部视图，问题/输出状态为辅助区，文件标签属于组，外层仍是统一工作区标签。复用共享 Dialog、图标和设置控件，窄窗口可折叠辅助区但保持文件关闭、保存与错误可访问。Markdown/图片渲染沿用现有安全路径，Diff 两侧临时 model 与常规编辑 model 分开管理。

左侧导航中的 editor 是直接打开工作台的动作，复用已有导航显示设置和存储键；新用户默认显示，已保存的显隐选择原样保留。点击进入本地空工作台，可直接选择本地文件或目录。主窗口与独立工作台共用相同入口和窗口归属检查；隐藏图标不销毁已打开文档，也不改变命令面板入口。

### 8. 生命周期、窗口与持久化

关闭采用两阶段协调：先收集当前范围的 dirty 文档决定及运行终端确认，所有决定通过后才提交文档关闭/会话释放；保存失败或取消终止资源销毁。锁定与正在关闭时拒绝新的文件写入；已发出的保存允许完成并更新基线，不能在解锁后悄然重复提交。

移窗选择先保存/放弃再传干净状态，不实现热迁移 dirty 正文。窗口交接只携带来源、路径、布局与视图位置；目标确认前保留源视图，失败不销毁源工作区。远端授权和操作归属需在后端按调用窗口校验，不信任前端传入任意窗口标签。不得通过全局事件广播文件正文。

新增独立本机偏好和干净工作区元数据，跨窗口只同步偏好；重启恢复布局与文件引用时重新检查文件和授权，远端恢复不能跳过认证/TOFU。不存正文、撤销栈或 dirty 草稿；正常退出有保护，进程崩溃仍可能失去未保存修改，不能对用户声称已备份。保留既有编辑设置键及连接导入导出语义，无需求不新增 DB 表；确需 DB 时使用编号迁移。

## Risks / Trade-offs

- [文件编码、原子替换和服务端元数据差异] → 同目录临时文件、内容 token、能力探测、失败保留、明确降级与真实服务器验收。
- [1 GiB 上限与 WebView 可承受容量不同] → 普通预算、受限模式、取消与内存观测；硬上限不等于交互性能承诺。
- [跨文件替换部分成功] → 确认前逐文件预览、应用前版本重验、逐项结果与取消，不承诺自动回滚。
- [React wrapper 卸载误释放共享 model] → 注册表单一所有权、引用计数和 StrictMode/分组关闭回归。
- [扩展到工作台容易破坏快捷键/移窗/锁屏] → 独立分组树、统一命令路由、关闭两阶段协调、原生两窗口验收。
- [不提供默认磁盘草稿意味着崩溃无法恢复] → 明确仅正常关闭保护；后续若要求热退出/恢复，独立设计敏感内容持久化，不偷加明文缓存。

## Migration Plan

1. 先实现共享内核、版本化文件服务和新 Monaco 外壳，保留旧入口可用；旧服务签名不破坏性变更。
2. 新工作台接入后，将旧 SFTP 文本分支适配到共享内核；既有图片/Markdown、双栏独立 dirty 和代码图片工具同步回归。
3. 新偏好缺省读取旧编辑设置，不重命名已有键。回退版本可以忽略新增键，文件字节仍为标准编码；不依赖反向数据库迁移。
4. 全部核心任务及两平台安装包、真实 SSH 验收完成前不标记稳定发布；文档与验证证据按既有目录分工维护，任务状态仅维护在本 change。

## 界面整理补充（2026-11-26）

采用外层工作台标签、单行分组图标工具栏、内部可调 Explorer/搜索与文件分组、状态栏的层级；次要命令在窄空间收入溢出菜单。编辑工作台使用统一窗口/文本图标，文件标签保留文件类型图标；自动显示编号与来源仅用于辨识，不覆盖原始名称。侧栏直接展示文件树/搜索，已打开文档统一由文件标签管理，资源侧栏宽度单独本机保存，不存正文。独立窗口入口复用已实现的整工作台移窗协调。布局参照 [VS Code Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout)，外观继续使用本项目控件与语义 token。

### 文件标签栏快捷操作

每组文件标签栏右端固定显示保存、按类型显示的 Markdown 预览、向右分屏与更多操作，标签区独立收缩滚动。按钮复用共享图标控件、语义配色和悬浮名称；预览绑定分组与文档身份，开启状态与实际预览一致，跨组操作先明确所属组，不依赖上一次焦点。更多操作保留向下分屏及既有文件动作；主工具栏继续保持单行。锁屏、交接、只读保存及大文件预览沿用既有保护。

### 简约布局与树上下文操作

保持单行分组工具栏、固定文件标签动作及状态栏；宽屏来源区域改为工作区快捷打开入口。标签、侧栏与正文通过共享语义表面和克制边界区分，文件图标复用 FileEntryIcon 的类型映射与配色。文件切换动效使用独立、不可命中的覆盖层，只重建装饰节点而不重新挂载 Monaco/model；减少动态效果下移除动效。

EditorFileTree 发出明确的选择快照与鼠标/键盘锚点，EditorFileManagement 持有菜单、对话框和文件操作生命周期；右键保留已选多项，空白区域使用根目录。上下文菜单复用共享菜单键盘导航和语义控件，限制于视口，滚动/失焦/锁屏/交接时关闭。创建、重命名、移动、复制和删除仍走既有 performFileMutation 与后台窗口归属/根目录/排他创建保护，不增加第二条写入路径。新建成功先解除 busy，再刷新定位并打开文件，防止被正在操作保护错误阻断。

### 空工作台原位打开目录

### Markdown 所见即所得视图

使用离线懒加载的 Tiptap/ProseMirror 作为 Markdown 富文本视图，Monaco registry model 继续作为唯一正文和撤销/保存来源，不持久化富文本 JSON。按 remark GFM 顶层语法位置切分源码区块，记录原文、分隔空白及富文本语义指纹；未变化区块输出原文，变化区块通过 Markdown 序列化器输出。不能可靠往返的语法保留原文区块，避免依赖全篇 HTML/Markdown 转换造成数据丢失。原始 HTML 与图片引用只显示安全原文/占位，不注入可执行 HTML 或发起文档外部资源请求。

富文本模型变更以最小替换提交 Monaco 撤销栈；自发更新不重建视图，其他分组/源码/撤销更新在非组字时同步。视图独立 retain/release 文档，关闭保护与初始化 ready 覆盖富文本视图，锁屏/只读/交接同时阻断输入与晚到变更。模式使用共享分段控件，格式和表格操作采用单行分类菜单，沿用语义配色；大文件回到源码，加载失败保留源码入口。

资源管理器顶部使用共享 Icon 的轻量线性字形，新建文件/目录与显示/定位/刷新以小间距及轻分隔分组；隐藏项开关同时显示选中态与眼睛开闭字形。目录刷新复用编辑器刷新按钮，真实请求状态驱动忙碌、禁用和持续旋转，短请求保留 600ms 图标反馈但不延迟请求完成或阻塞下一次操作；定时器卸载清理。树的刷新世代保护确保旧完成不会清除新操作状态，失败保留已有条目及重试入口；减少动态效果关闭旋转但保留状态与提示。

Workbench 订阅注册表每次同步提交，记录文档身份键；首次保存和另存为成功改变身份后，在当前根内排队一次树同步，不依赖各个按钮或保存 Promise 的调用点。同步订阅确保关闭时保存即使紧接着释放模型也不会漏掉路径。刷新已有展开目录并通过原 reveal 定位最后保存目标，批量提交可合并；隐藏、搜索面板、后台、锁屏/冻结/交接或文件变更期间延后，恢复可见可用后执行，不强制展开侧栏或改变根目录。失败/取消和普通编辑不改变身份，不触发同步；根外和无根工作台不隐式切换目录。

### 平整交互状态与富文本代码围栏

全局常用选中项和编辑器模式、标签采用语义背景色与常规边界，移除单边粗线和内嵌强调阴影；保留键盘焦点、内容引用和功能性箭头等必要图形。
