## Context

共享 Button/IconButton 已有背景反馈，但无统一轻阴影；原生 button 的默认 cursor 仍是箭头。多数菜单使用 role=menu/menuitem，文件菜单和标签菜单保留真正的 disabled 属性。编辑器将同一动作列表同时供应用菜单和原生菜单使用。

## Goals / Non-Goals

统一行为反馈而不改变授权和动作执行条件；菜单和工具栏只呈现可用动作。表单中的禁用按钮保持可见，不做全局隐藏所有 disabled 控件。保持文本输入、原生窗口拖动、分隔条和可拖动元素的指针语义。

## Decisions

- 共享 CSS 兜底语义按钮、链接和可操作角色的指针；阴影使用新的轻量语义 token，仅用于可用的共享按钮，沿用快速过渡，不做缩放或布局位移。
- 编辑器动作列表在渲染前过滤，空菜单入口和空分组不显示，原生模型同样过滤 disabled/blocked 并保留原动作 id 与执行检查。动态能力更新继续走现有刷新机制。
- 其他基于 DOM 的菜单与明确的工具栏通过统一可用性显示规则处理，保留真正的 disabled 属性确保隐藏动作也不能被误调用。设置表单、listbox 选项和文件列表不是动作菜单，不套用隐藏规则。
- AI 会话菜单按可用性条件渲染，分隔符跟随非空动作组。

## Risks / Trade-offs

- 动作随状态出现/消失会改变菜单尺寸 → 保留菜单定位和键盘焦点恢复，并验证空编辑器、单标签及可用性恢复。
- 全局 CSS 可能覆盖专用指针 → 不选中文本输入和拖拽目标，限定悬停阴影到共享控件并检查禁用/拖动区域。
- 原生系统项的可用状态由 OS 管理 → 本次只过滤应用提供的编辑器命令模型，原生 WebView 安装包仍需平台验收。
